# 展示替代方案

对比解决同一问题的不同方法。

## 使用方式

```
/learn:alternatives              # 对比当前代码的实现方案
/learn:alternatives auth         # 对比身份验证方法
/learn:alternatives state        # 对比状态管理方案
/learn:alternatives --detailed   # 包含每种方案的代码示例
```

## 执行步骤

1. 从上下文或参数中明确**待解决的问题**
2. 列出 **3-5 种替代方案**
3. 对每种方案说明：
   - 是什么（一句话描述）
   - 适用场景
   - 权衡取舍（优缺点）
4. 根据上下文给出**推荐方案**
5. 可选：为最优方案提供代码示例

## 评估维度

标准评估维度（根据问题灵活调整）：

| 维度 | 说明 |
|------|------|
| **复杂度** | 实现和维护的难易程度 |
| **性能** | 运行速度、内存占用 |
| **包体积** | 对前端打包体积的影响 |
| **学习曲线** | 理解并正确使用所需时间 |
| **灵活性** | 扩展或修改的便利性 |
| **生态社区** | 文档完善度、生态系统、社区支持 |
| **可测试性** | 测试的容易程度 |
| **类型安全** | TypeScript 支持质量 |

## 深度模式

### 默认模式
- 3-4 种方案
- 简要描述每种方案
- 对比表格
- 推荐建议

### `--detailed`（详细模式）
- 4-5 种方案
- 每种方案附代码示例
- 详细权衡分析
- 迁移注意事项
- 真实案例参考

### `--quick`（快速模式）
- 2-3 种方案
- 每种方案一行说明
- 快速推荐

## 示例会话

```
User: I'm using useState for form state. /learn:alternatives

Claude: ## 问题：React 表单状态管理

### 方案 1：多个 useState

**是什么**：每个字段独立使用 useState

**适用场景**：
- 简单表单（< 5 个字段）
- 无复杂校验逻辑
- 字段间无依赖关系

**优点**：简单直接，无依赖，易于理解
**缺点**：字段多时代码冗余，状态分散

---

### 方案 2：单个 useState + 对象

**是什么**：用一个 useState 将所有字段存为对象

**适用场景**：
- 中等规模表单（5-10 个字段）
- 需要一键重置整个表单
- 追求更整洁的代码

**优点**：状态集中，易于重置，代码更清晰
**缺点**：需要展开运算符，可能触发不必要的重渲染

---

### 方案 3：useReducer

**是什么**：用 Reducer 模式处理复杂状态转换

**适用场景**：
- 复杂校验逻辑
- 多步骤表单
- 撤销/重做功能

**优点**：状态更新可预测，处理复杂逻辑，易于测试
**缺点**：样板代码多，有学习成本

---

### 方案 4：表单库（React Hook Form、Formik）

**是什么**：专用表单状态管理库

**适用场景**：
- 大型表单（10+ 个字段）
- 复杂校验（异步、跨字段）
- 性能敏感场景（字段数量多）

**优点**：优化重渲染，内置校验，代码量少
**缺点**：引入依赖，有学习成本，增加包体积

---

## 对比表格

| 维度 | useState | useReducer | React Hook Form |
|------|----------|------------|-----------------|
| 复杂度 | 低 | 中 | 中 |
| 性能 | ★★☆ | ★★☆ | ★★★ |
| 包体积 | 0kb | 0kb | ~8kb |
| 校验 | 手动 | 手动 | 内置 |
| 最适合 | 简单表单 | 复杂逻辑 | 大型表单 |

## 推荐

**针对你的情况**：如果是简单的登录/联系表单，继续用 **useState** 即可。如果是多步骤结账或后台管理表单，推荐 **React Hook Form**，可获得校验和性能优势。

**考虑 useReducer 的情形**：需要撤销/重做、复杂状态机，或希望以 Reducer 风格编写测试时。
```
